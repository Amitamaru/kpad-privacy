це окремо розкрито на сторінках.

## Завантаження на GitHub Pages — власником

1. Створити окремий публічний GitHub-репозиторій для політики. Його назву й
   обліковий запис GitHub власник ще не визначив у цьому завданні.
2. Завантажити **лише вміст цієї папки** в корінь репозиторію: `index.html`,
   `en/index.html`, `.nojekyll` та за бажанням цей README. Не завантажувати весь
   Android-проєкт, `.diagnostics`, архіви, ключі або результати Android-збірки.
3. У GitHub Settings → Pages вибрати **Deploy from a branch**, потрібну гілку
   та папку **/(root)**, зберегти налаштування. `.nojekyll` вимикає обробку Jekyll.
4. Дочекатися успішного Pages deployment та скопіювати **фактичну HTTPS-адресу**,
   яку показує GitHub. Українська версія відкривається в корені сайту, англійська
   — за відносним шляхом `en/`. Власний домен необов’язковий.
5. Перевірити обидві мови, UK/EN, тему, email та посилання змісту на опублікованому
   сайті. Використати отриману адресу в Google Play Console як Privacy Policy URL.

У цьому завданні репозиторій GitHub не створювався, push/Pages deployment/Play
upload не виконувалися. Фактичної публічної адреси ще немає, її не вигадано.
Після публікації перевірити адресу без авторизації в GitHub.

## Звідки взято текст

У вихідному Android-проєкті вже були `docs/privacy/privacy-uk.html` та
`docs/privacy/privacy-en.html`. Канонічні тексти — `docs/PRIVACY_POLICY_UK.md`
і `docs/PRIVACY_POLICY_EN.md`, однакові з відповідними Android assets.
Ці оригінали не змінено.

Вебсторінки генеруються з тих самих семи змістових абзаців командою
`python scripts/prepare-privacy-pages.py` з кореня Android-проєкту. Скрипт
перевіряє відповідність docs/assets, додає оформлення, навігацію, конкретні
дозволи з manifest і розкриття щодо вебхостингу. Чернетковий вступ із порожніми
реквізитами замінено датою, версією та наданими реквізитами; єдине речення
«контакт буде заповнено» замінено реальним контактом. Решта семи абзаців
залишається дослівною. Це похідне оформлення, а не окрема незалежна політика.

Вбудована політика у вже прийнятому застосунку/AAB усе ще має старі поля
видавця/email/URL. Цей публічний сайт їх заповнює без зміни функціональності.
Оновлення вбудованого тексту чи `privacy_public_url` потребуватиме окремої
версії застосунку; фінальний тег `v1.1.0` і підписаний AAB не змінювалися.

## Результат технічної звірки

Звірено з прийнятим кодом `prototype/src/main`, manifest, Gradle runtime
dependencies та `docs/BACKUP_AND_RESTORE.md`, `ARCHITECTURE.md`,
`KNOWN_LIMITATIONS.md`, `PLAY_DATA_SAFETY.md`.

| Тема | Фактична поведінка, розкрита в обох мовах |
|---|---|
| SMS/MMS | Android Provider, явна SMS-роль, `SmsManager`; передавання оператору/отримувачам, без обіцянки E2EE або перевіреного операторського MMS |
| Контакти | Необов’язковий READ_CONTACTS, імена/номери/групи/обране, ручний номер; немає WRITE_CONTACTS |
| Дозволи | Точні 10 uses-permissions з production manifest; SIM, notification, vibration, boot; немає INTERNET/camera/microphone/location/broad storage |
| Локальні дані | Системна історія окремо від приватних drafts/templates/settings/cache/attachments/operations; кеш не backup |
| Передавання | Немає developer backend, реклами, telemetry SDK або прямого HTTP; оператор, явні clipboard/viewer/camera/SAF дії та окрема системна IME мають власні правила |
| Backup | Явне створення приватного незашифрованого ZIP2 з SMS/MMS/parts і локальними даними; старі перевірені архіви автоматично не стираються |
| SAF | Явний експорт готового архіву/вибір імпорту; хмарний destination можливий за вибором користувача; при write error може залишитися частковий зовнішній файл |
| Restore | Preview до окремого confirm, actual SMS role, add-only/dedup; real system restore acceptance не завершено; invalid/partial imports можуть залишитися приватно |
| Зберігання | allowBackup=false/fullBackupContent=false, Android12+ extraction exclusions; без гарантії видалення системних SMS або зовнішніх файлів через uninstall |
| Приватність сповіщень | Hide content зберігає sender у відкритій шторці, видаляє SMS body; active-only quiet updates, Android lock screen має пріоритет |

Політика не обіцяє, що жодні дані не залишають телефон, що ZIP зашифрований
або що SHA-256 доводить можливість системного відновлення.
